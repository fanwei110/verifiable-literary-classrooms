# Supplementary Methods: LLM Judges under Closed, Retrieved, and Gold-Reference Evidence

## Evaluation set and evidence conditions

We evaluated model-based quotation verification on a frozen, stratified set of 60 items. The set contains 12 deterministically correct controls and 48 deterministically incorrect items, with 12 items in each of four error classes: fabricated quotation, misattribution, version drift, and context displacement. Each item was presented under three evidence conditions. The `closed` condition supplied only the quotation claim and its declared work, location, and speaker. The `rag_top3` condition additionally supplied the three highest-ranked passages returned by dense retrieval over the complete six-work corpus. The `gold_reference` condition instead supplied the source window and canonical metadata frozen with the original task. It did not reveal the deterministic label, error class, or any field-level verifier output. Consequently, the three conditions differed only in their evidence block; the task instruction, response schema, item set, and model-specific inference configuration were held fixed.

The gold-reference condition is named to describe the provenance of its evidence, not to claim an oracle performance bound. The source window was inherited from the task used to generate and score the original quotation claim. A hidden item-to-task mapping attached the corresponding window and canonical metadata before prompts were frozen. This mapping was never exposed to either judge, and the prompt-leakage tests reject any occurrence of the deterministic verdict or error label.

## Retrieval construction

Dense retrieval used the local `all-MiniLM-L6-v2` sentence-transformer. All six frozen works were segmented at approximately 700 characters with 150-character overlap, producing 4,775 candidate passages. Each claim was searched against the pooled cross-work index rather than an index restricted to the declared work. This design is important for misattribution items: restricting retrieval to the claimed work would encode the model's attribution in advance and could conceal cross-work errors. Cosine similarity determined the top three passages. The frozen manifest records three diagnostic hit indicators—exact quotation hit, original task-window hit, and a composite diagnostic hit—so that retrieval failure can be separated from judgment failure.

## Judges and isolation

The first judge was `gpt-5.6-sol`, invoked through `codex-cli 0.144.6` using the user's authenticated ChatGPT/Codex subscription. This arm is therefore reported as a **Codex CLI subscription judge**, not as an OpenAI API experiment. Every item-condition pair ran in a separate ephemeral session in an empty working directory, with user configuration ignored, a read-only sandbox, and a JSON output schema. Automatic skills instructions and bundled skills were explicitly disabled, as were shell, browser, application, computer-use, image-generation, collaboration, and workspace-dependency capabilities. The prompt also prohibited tool use. The complete CLI JSONL event stream was retained for each request; any tool event or client error/skills-injection event invalidates the batch.

The second judge was `deepseek-v4-pro`, called through DeepSeek's official Chat Completions endpoint. Thinking mode and `reasoning_effort=high` were fixed, while unsupported sampling controls such as `temperature` and `top_p` were omitted. JSON Output was enabled, and the final formal batch used a uniform `max_tokens=65536` safety ceiling because preflight runs showed that high-thinking reasoning could occasionally consume 16,384 tokens before emitting the final JSON. Raising this ceiling changes only the truncation boundary; the model, prompt, reasoning effort, thinking mode, and response format remain fixed. The $10 API budget includes smoke tests, preflight calls, failed requests, and formal calls; a conservative peak-price ledger stops new dispatch at $9.75.

Both judges returned the same four fields: `verdict` (`accurate`, `inaccurate`, or `unsure`), confidence on a 0–1 scale, a concise rationale, and cited evidence. Each raw record retains the item and condition identifiers, prompt and request hashes, final parsed JSON, timestamps, status, and attempt number. GPT records additionally retain the CLI version, model identifier, available token usage, event-log path, and tool-use flag. DeepSeek records additionally retain the returned model, system fingerprint, token accounting, request configuration, and both contemporaneous-tariff and peak-price costs. The DeepSeek key was read only at runtime and was excluded from requests logs, exception text, commands stored in the experiment directory, and replication outputs. The OpenRouter credential was neither read nor used.

## Statistical analysis

For the 48 incorrect items, we report error-detection, false-acceptance, and `unsure` rates. For the 12 correct controls, we report correct-acceptance, false-rejection, and `unsure` rates. The strict primary analysis counts `unsure` as an incorrect classification; a sensitivity analysis recomputes accuracy after excluding `unsure`. Wilson 95% confidence intervals are calculated for correct controls, all errors, and each of the four error classes. Within each judge, the three evidence conditions are compared item by item with exact McNemar tests, with Holm adjustment over the three pairwise comparisons. Cross-judge differences are treated descriptively because the two inference systems do not constitute paired stochastic replications of a common model.

For the RAG condition, performance is also stratified by the three frozen hit definitions. This decomposition distinguishes failures caused by retrieval from failures that persist despite the relevant passage being present. No comparison is described as performance "above chance," because the three-way verdict task and stratified class distribution do not justify that benchmark.

## Reproducibility boundary

The reproducible object is the frozen prompt manifest, evidence construction, request configuration, hashes, raw event or API responses, parsing rules, and analysis code. Model outputs are retained as one-time observations and are not claimed to be bitwise reproducible. GPT subscription calls are reported by call count and any subscription interruption, without inventing a dollar-equivalent API charge. The deterministic verifier remains exactly reproducible for the frozen corpus; its advantages are described as deterministic corpus-membership decisions, auditability, and the absence of an additional model call, rather than as a presupposed accuracy advantage over every language model.
